How It Works

The pipeline, step by step

Every invoice follows the same path. The system handles the mechanical steps; humans make the approval decision.

1

Invoice Arrives

An invoice lands via Gmail attachment, Google Drive upload folder, or web form. n8n detects it, archives the original PDF to Drive with a standardised filename, and passes the raw bytes to the backend.

Gmail trigger Drive monitor Web form
2

AI Extraction

The PDF is sent directly to Gemini (Google's multimodal AI). Gemini reads the document — including scanned/handwritten invoices — and returns a strictly structured JSON object with every field. No OCR preprocessing needed.

Gemini native vision Function-calling schema Pydantic validation
3

Vendor Normalisation

The vendor name is cleaned up and matched to your known vendor list. "Sherwin Williams", "SHERWIN-WILLIAMS CO.", and "Sherwin Williams Paint" all collapse to one canonical record. Uses exact match → fuzzy match → AI fallback.

Exact lookup Fuzzy match AI fallback
4

Validation & Duplicate Detection

Math is checked (subtotal + tax + shipping − discount = total). Required fields are verified. The invoice is fingerprinted by file hash and checked against all previously seen invoices — exact and near-duplicate matches are flagged.

Math check Required fields Hash dedupe Semantic dedupe
5

Approval Routing

Based on the invoice total, the system assigns a tier. Small invoices are auto-approved. Mid-range invoices trigger a manager approval email. Large invoices trigger a CFO approval email with one-click Approve / Reject links.

Auto (under $500) Manager ($500–$5,000) CFO (over $5,000)
6

Sync to Systems

Once approved, the record is written to Google Sheets (the master dashboard), QuickBooks Online (as a Bill), and Jobber (as an Expense). Each target is independent — if QuickBooks is down, Sheets and Jobber still succeed.

Google Sheets QuickBooks Online Jobber
7

Weekly Report

Every week the system generates a finance ops summary: how many invoices processed, total value, top vendors, exception rate, and any sync failures. Emailed to the owner automatically.

Invoice count Total value Exception rate Top vendors

Approval Routing

The right person approves every invoice

Thresholds are configurable per client. The system routes automatically — no manual triage needed.

⚡

Auto-Approved

Under $500

Small routine invoices are approved automatically and synced to Sheets, QuickBooks, and Jobber immediately. No email sent.

👔

Manager Approval

$500 – $5,000

An approval email is sent to the manager with one-click Approve / Reject links and invoice details. Sync only runs after approval.

🏦

CFO Approval

Over $5,000

An approval email is escalated to the CFO. Same one-click flow. Rejection triggers a notification email; no financial records are written.

Exception Handling

Problems are caught, not passed through

Any invoice that fails a check is routed to the Exceptions tab in Google Sheets — visible, labelled by severity, and assignable for review. Nothing silently disappears.

High

Duplicate invoice detected (same hash or same vendor + amount + date)

High

Math mismatch — subtotal + tax ≠ total beyond $0.02 tolerance

High

Missing total amount — cannot validate or route

Medium

Low confidence score — AI was uncertain about extracted values

Medium

Missing invoice number — cannot uniquely identify for records

Medium

Possible duplicate — same vendor and amount, different file

Low

Unknown vendor — not in the vendor normalisation list

Low

Missing PO or Job ID — may affect job-cost tracking

System Sync

Approved invoices sync to three targets

Each target is independent. If one fails, the others still succeed and the failure is recorded in the sync status column.

📊

Google Sheets

The primary dashboard and audit log. Written first, before other systems.

  • Invoices tab with all extracted fields
  • Line items in a separate tab
  • Exceptions tab for review queue
  • Approval metadata (who, when, notes)
  • Sync status for each target
  • File hash for audit trail
💼

QuickBooks Online

Creates a Bill record in the client's QuickBooks account, mapped to the correct expense account.

  • Bill created with line items
  • Vendor matched or created
  • QB Bill ID stored in Sheets row
  • Only runs after human approval
🔧

Jobber

Creates an Expense entry in Jobber, linked to the job or client where applicable.

  • Expense created via GraphQL API
  • Job ID mapped if present
  • Jobber Expense ID stored in Sheets
  • Only runs after human approval
Audit trail: every Sheets row records approved_by, approved_at, approval_notes, sync_status, and the SHA-256 file_hash of the original PDF. You can always trace any record back to the original document.
Security & Controls

Built with controls that finance teams expect

The system is designed so that no money moves without a human decision, and no data leaks outside authorised systems.

🔑
API Key Authentication

Every request to the backend requires an X-API-Key header. Unauthenticated calls are rejected with 401.

👤
Approver Allowlist

The approval callback validates that the approver email is in a configured list. Spoofed callbacks are rejected.

🚫
No Autonomous Payments

The system never pays bills. It only writes records. Financial system updates require an explicit human approval click.

🔒
Server-Side Hash & Filename

file_hash and file_name are always assigned by the server after reading the PDF — never trusted from AI output or user input.

🛡️
Prompt Injection Hardening

The AI system prompt explicitly instructs the model to ignore any instructions embedded in the invoice document itself.

📏
File Size & Type Guards

Maximum 20 MB. PDF magic bytes verified before processing. Non-PDFs return 415 — they never reach the AI.

🔐
Secrets in Environment

All API keys (Gemini, QuickBooks, Jobber, Google) are stored in environment variables — never hardcoded or logged.

📋
Zero Silent Failures

Every sync failure is recorded in the Sheets row. Every exception is written to the Exceptions tab. Nothing disappears quietly.
